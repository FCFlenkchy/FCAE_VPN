FIXED: Cross-compilation wintun.dll embedding
==============================================

Previous issue (shown in original build log):
  - Building aether-engine for windows/amd64 FROM a Linux CI runner
  - embed_wintun_dll() was gated with #[cfg(target_os = "windows")]
  - This meant the function was NEVER compiled on Linux hosts
  - Result: wintun.dll was silently NOT embedded → runtime crash on Windows

Changes made to core/aether-engine/build.rs:
  1. Removed #[cfg(target_os = "windows")] from embed_wintun_dll()
     → Function is now always compiled; TARGET_OS check is at runtime
  2. Removed #[cfg(target_os = "windows")] from download_wintun_dll()
     → Download now works on any host OS
  3. Added host-OS-aware download methods:
     - Windows: PowerShell → curl
     - Linux:   curl → wget
  4. Added host-OS-aware extraction methods:
     - Windows: PowerShell Expand-Archive → tar
     - Linux:   unzip → 7z
  5. Added find_file_in_dir() helper for recursive DLL search in zip output
  6. Added proper cleanup of temp files

Cross-compilation flow is now:
  Linux CI runner → cargo build --target x86_64-pc-windows-gnu
    → build.rs detects CARGO_CFG_TARGET_OS=windows
    → Calls embed_wintun_dll() (runs on Linux host!)
    → Downloads wintun-0.14.1.zip via curl/wget
    → Extracts with unzip/7z
    → Copies wintun.dll to OUT_DIR
    → Sets cfg=wintun_embedded + WINTUN_EMBEDDED env
    → tun_t2s.rs includes wintun.dll bytes in the binary ✓
